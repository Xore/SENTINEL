CUSTOM TARGET

Run an action against any host

TCP connect only (no UDP scan, no version detection, no scripts) — read-only. OT/ICS ports are marked in the picker; only touch them inside a change window. Every action is logged to Assets → history.

ACTIVE · ALLOW-LIST GATED

Traffic generator

Sends bounded TCP/UDP payloads to a destination. Active action: only allow-listed destinations are permitted — add yours below, then send. Never point it at production OT without a change window.

INVENTORY

Observed hosts

Every address the probe has seen or scanned — from discovery, SNMP, LLDP, traces and reachability. Persisted across restarts. Click a row for its per-host history.

HISTORY

Scan & action log

Durable log of every operator-initiated action and its outcome.

BROAD VIEW

LAN host discovery

Light ICMP/ARP host sweep of a directly-connected subnet plus the neighbour cache — IP, MAC, vendor and reverse-DNS name. Host discovery only, no port scan, never a payload to OT devices.

PASSIVE DIAGNOSTICS

Short Layer-2 health sample

Reports traffic rate, broadcasts, multicast, ARP, STP, discovery, OT protocols, retransmissions, resets and NIC drops.

SUPPORT BUNDLE

System/network snapshot

Records interfaces, routes, neighbors, DNS, time, driver counters, sockets and Wi-Fi state. The local result is hashed.

HEALTH PROFILES

Run a profile against a target

Path route, path-MTU, latency and loss (tracepath + ICMP). Services DNS, clock, TCP, TLS and HTTP. Infrastructure read-only SNMP identity/interfaces (uses Settings credentials). Baselines 7-day median/p95 latency and loss vs the last hour, from the outage monitor's history. All read-only / safe-active.

OT profilesOPC UA / validated read-only S7 stay change-window gated — run them from the Actions console against a single OT endpoint, never as a background profile.

SPATIAL MAP

AP proximity map

A radial map of the access points around this probe. Distance from the centre tracks signal strength (stronger = closer); angle is spread for legibility — a single antenna can't sense true bearing, so this is proximity, not a compass. The AP this probe is associated with is highlighted.

ROAM / HANDOVER LOG

Wi-Fi event log

Roaming, (re)association, drops and link warnings, derived from the 5-second link samples the monitor records. blue = information (handover / associated) · yellow = warning (weak signal, TX failures, beacon loss) · red = error (disconnected / roam failed).

CONTINUOUS RF WATCH

Access points

A background scanner records every AP it can see and logs the moment one disappears (stops beaconing) or a new one appears. Unprivileged nmcli — needs the radio enabled; interval is set in Settings → Monitor. An empty scan (radio blocked) is ignored, never counted as a mass disappearance.

CAPTURE ADAPTER

Which NIC(s) Suricata watches

Choose how the IDS picks its capture interface. Auto follows the best connected NIC; All captures on every up NIC; Specific lets you tick a set (a down/prepared NIC is bound the moment it comes up). A root daemon enacts the change, validates the config, and rolls back on failure — the dashboard never touches Suricata directly.

INTRUSION DETECTION

Signature alerts (Suricata)

Passive signature-based IDS on the monitored interface (ET Open ruleset). Detection only — Suricata never blocks or alters traffic. If it is not installed, run sudo scripts/install-ids.sh --apply on the probe. Click any IP for its full dossier; click Details on an alert for every correlated event (domain, path, headers, DNS, TLS).

TOPOLOGY

LLDP / CDP neighbours

Which switch and port the probe is plugged into, from LLDP/CDP frames collected by lldpd (receive-only). Not installed? Run sudo scripts/install-neighbors.sh --apply.

DEVICE IDENTITY

SNMP probe

Read-only single-host SNMP identity read (sysName/Descr/location, optional interface list) using the credentials in Settings. One host at a time — not a sweep.

CAPTURE CONTROL

Interfaces

Enable an interface for capture / monitor / health jobs. Interfaces without an IP are eligible by default; enabling one that carries an IP (e.g. the management link) lets you capture on it too — you will be sniffing your own management traffic, so use it deliberately. USB adapters are detected automatically.

CREDENTIALS

SNMP

Stored on the probe only (owner-readable). Leave a secret field blank to keep the current value.

SERVICE CATALOG

Custom services

Save your own named ports (e.g. plc-line3 · 2404/tcp). Saved services appear in the Actions “known service” picker under Custom and persist across restarts. Reference labels only — they never change how a probe runs.

OUTAGE MONITOR

What to probe

Edit who the always-on outage monitor pings, which services and TCP ports it checks, and how often it scans for access points. Saved to a config the monitor hot-reloads within seconds — no restart.

Each probe has an enabled checkbox (include it at all) and a ▶/⏸ start/stop toggle (its live run state). A probe runs only when it is both enabled and started. New probes are added stopped. Start all starts only the enabled probes (so a probe you keep disabled — e.g. an OT check — is never started in bulk); Stop all stops everything. Toggles save and hot-reload immediately.

Ping targets

The interface column picks which adapter each target is probed over (ping and the traceroute/hop-quality probe are both sourced from it). Leave it on auto to let the OS route it. Binding a target to a specific adapter tests that path independently — e.g. the wired uplink vs. a secondary NIC.
